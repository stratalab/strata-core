# #3596 — Space reclamation contract: root cause, design, and paired implementation + test slices

Status: **APPROVED 2026-09-26 — implementation in progress** (milestone 1.2.6, issues #3591–#3600; evidence on #3493). This document is slice 0 of the plan it describes; every slice PR links back here and updates the ledger in §4.

Provenance: three read-only exploration passes (maintenance executor and session lifecycle; the three reclaim proofs and branch topology; test harnesses and diagnostics) and three design passes (scheduling contract; multi-branch proofs and snapshot lifecycle; observability and tests), reconciled against measurements of the failing database. Every symbol below was verified on `main` @ `e95167d7`. Field tools used for the measurements live outside the repo (`/data2/strata-probe/tools/dbsize.py`); after slice 10 the product reports the same facts itself.

## 1. Context

A 1.2.5 durable-local database written through the Python SDK (`strata-turn`, 1,893,851 events, 79 MB CSV) weighed **952 MB**. The earlier storage-amplification work (#3492: Zstd tables, opt-in MVCC pruning) did its job — live tables are 250 MB at 65 B/row — but three reclaim paths never ran:

| component | bytes | status |
|---|---:|---|
| tables referenced by the branch manifest (3,833,395 rows = exactly the live count) | 250 MB | live |
| table objects referenced by nothing (59 files, 5.03 M rows; 5 byte-identical twins of live tables) | 331 MB | dead |
| checkpoint snapshots 1–5, superseded by snapshot 6 | 191 MB | dead |
| snapshot 6 (manifest-live) | 21 MB | live |
| WAL segments 11–14, all below the flushed commit except a 2.8 MB tail | 195 MB | dead |

Control runs (same SDK, fresh directories): write 6 s + immediate close → 47 MB table debt; write + 30 s idle + close → 0 table debt; reopen read-only + idle → nothing reclaimed; reopen + one append + idle → all reclaimed. A clean-close reload of the real CSV with 90 s idle still weighed 642 MB (249 live, 185 MB dead snapshots, 204 MB flushed WAL), and took 16.8 s to open because it replayed that WAL. The same CSV is 20 MB in DuckDB, 23 MB in LanceDB, 99 MB in SQLite (flat); the 1.89 M-row event-log shape is 74 / 84 / 262 MB.

Direction from the user: no per-issue patching; fix the root cause with a written design, then implement, with every implementation slice paired with its tests. Decisions taken with the user on 2026-09-26: the per-branch format extension ships in 1.2.6 (so the island shape from #3493 is fixed too), and a clean close checkpoints.

## 2. Root cause

**One sentence:** every reclaim family in the durable lifecycle has a sound proof and a working deleter, but reclamation is scheduled only as best-effort background work inside a write session and is discarded at every session boundary; and for engine-opened databases the one lever that can release WAL — the checkpoint — is disabled at close and blocked by a single-branch assumption that the engine's mandatory `_system_` branch always violates.

Verified mechanisms:

1. **Close cancels reclamation.** `LifecycleDurableLocalRuntime::finish_close` (`crates/storage/src/lifecycle/durable/close.rs`) begins with `cancel_pending_for_close`, which keeps only tasks whose policy is `MaintenanceClosePolicy::DrainBeforeClose`. All 15 production task constructors in `crates/storage/src/lifecycle/maintenance.rs` use `MaintenanceTaskPolicy::coalescing()` (close policy Ordinary); the drain-before-close policies are used only by tests. The close runner maps the quarantine sweep to a no-op (`quarantine_task_without_request`). `StorageRuntime::close_with_options` (`api/runtime/mod.rs`) stops the background workers (250 ms) *before* the lifecycle close, so no drain round runs during close either. The close-time checkpoint defers whenever any non-seeded branch exists (`non_seeded_branches_present`), which is always true with `_system_`.
2. **Open never wakes the worker; nothing wakes an idle runtime.** Bootstrap enqueues one `table_object_retention` mark on reopen (`durable/bootstrap.rs`), but `open_durable_with_owned_backend_handle` never calls `notify_background_drain`; `BackgroundRuntimeController::notify_drain` (`api/runtime/background.rs`) is the only wake and is reached only from commits, public enqueues and the WAL-growth trigger. There is no timer. A sweep deferred by a held read view does not re-queue. Reclaim is low-tier, serviced once per `LOW_TIER_SERVICE_INTERVAL = 4` upper-tier tasks (`api/runtime/maintenance.rs`), so a sustained write firehose starves it (59 orphans accumulated in 55 s).
3. **Snapshots are never pruned.** `CheckpointService::checkpoint` (`service/checkpoint.rs`) publishes the new snapshot and re-points the manifest; the previous object is never touched. `SnapshotService::prune_snapshots` exists but has no autonomous caller (only the storage-API verb, which no engine or CLI surface calls, and the dead close runner). Its retain-newest-N rule would also protect a crash orphan (a newer id the manifest never attested) forever. Recovery loads only the manifest-attested snapshot (`recover_checkpoint`), so every other snapshot is pure garbage.
4. **WAL: the checkpoint is the only lever for an engine database, and it is blocked.** `wal_retention_watermark = max(snapshot_watermark, flush_watermark)`. The flush-watermark path cannot help: every engine database has two active branches (product default `[0x01;16]`, the storage-seeded branch; `_system_` `[0xf0;16]`, an independent root that receives every control-plane commit and in a typical session never flushes), so (a) the seven flush-watermark paths in `durable/maintenance.rs` that require `active_branch_ids() == vec![initial_branch_id]` never pass, and (b) even a multi-branch flush watermark would be pinned near zero by `_system_`'s unflushed control rows — excluding them is unsound (they would be lost with the truncated WAL). The checkpoint captures every branch's delta and is sound; but it runs only from the WAL-growth burst at 256 MiB retained (`lifecycle/config.rs`), never at close (mechanism 1), and for a database whose user branches have flushed it structurally defers forever (`non_seeded_branch_has_durable_base` in `lifecycle/checkpoint.rs`, the orphaned-delta guard) until recovery has a durable per-branch record of which branches hold a table-manifest base — which needs a format extension (`docs/architecture/archive/implementation-plans/storage-testing/multi-branch-orphaned-delta-recovery-gap.md`). In the 952 MB database retained WAL after snapshot 6 was 195 MB < 256 MiB, so no further checkpoint was attempted; in the 300 K-event repro none ran at all.
5. **Near-miss hazard.** The checkpoint delta (active + frozen memtable rows of every branch) is capped at `MAX_MATERIALIZED_SNAPSHOT_PAYLOAD_BYTES = 64 MiB` (`format/snapshot.rs`, cumulative over the container) while the active memtable rotates at `MAX_ACTIVE_ROTATION_BYTES = 64 MiB`; snapshot 5 was 62 MB. A breach is a hard `FormatError::InvalidLength` that fails the checkpoint and freezes the watermark; nothing bounds the delta first.
6. **Nothing is observable and nothing is gated.** Storage computes reclaim facts in memory (`DiagnosticsOutcome`) but the engine surfaces only control-plane health; the only byte counters are process-global `perf-trace` statics; no CI test asserts on-disk footprint; the DST simulation drains maintenance but never checks bytes.

Not the cause: table compression (already Zstd), MVCC version retention (append-only workload), the 64 MiB cap (no checkpoint was attempted after snapshot 6), or the loader's unclean exit (the clean-close control reproduces everything except the orphan count).

## 3. Design: the space-reclamation contract (new catalog entry DUR-019)

The proofs stay exactly as they are (COW-001, ARCH-005, ARCH-009, CMP-004, MVCC-009, DUR-016). The redesign changes **when** reclamation runs, **what a clean close does**, adds the per-branch durable record that lets the checkpoint run for every database shape, and makes all of it observable through one canonical path.

### 3.1 Session contract

| phase | what runs | what must not run | mechanism |
|---|---|---|---|
| **Open** (`OpenedExisting`) | after recovery returns, one reclaim-only *wake* (arm, never inline): table-object mark → quarantine sweep → purge; snapshot `ReconcileToAttested` prune | flush, checkpoint, flush-watermark, WAL truncation, rewrite (DUR-018); nothing inline in `open` | `notify_background_drain(Low)` after the runtime slot exists; per-database `ReclaimOnlyScope { Active, Inactive }` (Active until the first commit) consulted by pure `drain_scope_admits_upper_tier` in `start_next_background_step` |
| **Operation** | post-publish marks (existing); debt-aware low-tier service; after every `Completed` checkpoint: `Superseded` snapshot prune + WAL truncation (existing follow-up); growth-burst checkpoint with a bounded delta | — | `should_service_low_tier(upper_since_low, floor, debt_bytes, threshold)` replaces the fixed 1-in-4; `snapshot_pruning(Superseded)` enqueued from `run_checkpoint_follow_ups`; `checkpoint_delta_cap_decision` + flush-first |
| **Idle** | edge-triggered quiescence wake while reclaim is owed; re-arms reader-deferred sweeps | periodic empty polls (BS5.3) | `reclaim_owed` flag on the runtime; `quiescence_should_arm(round, close_requested)`; one delayed Low drain on the `MaintenanceClock` (deterministic under the manual clock), cancelled by `close_requested` |
| **Close** (clean) | 1 stop workers (250 ms) → 2 cancel non-drainable tasks → 3 bounded object-reclaim drain (fresh mark, inline sweep, purge) → 4 close checkpoint: multi-branch collector under `checkpoint_structural_deferral`, delta bounded by flush-first, WAL truncated with the snapshot proof, `Superseded` prune → 5 quiesce, `wal.close()`, release | — | reclaim kinds get `coalescing_drain_before_close()` via one `close_policy_for_kind`; the close runner gains a real sweep arm reusing `DurableTableObjectSweepRunner`; `StorageCloseOptions::reclaim_budget: ReclaimBudget { Disabled, Bounded(Duration) }` default `Bounded(500 ms)`; close checkpoint = `checkpoint_with_options(truncate_wal_after_checkpoint = true)` |
| **Crash / drop without close** | nothing; the next open reconciles | — | deliberate boundary: no `Drop`-based reclaim |

Result for the user's shape: a clean close leaves live tables + one small snapshot (the last delta) + an empty-or-tiny WAL, and the next open replays nothing. Every deferral has exactly one retry path (the quiescence wake or one bounded re-mark); nothing spins.

### 3.2 Multi-branch checkpoint (the format extension)

- **Write:** every checkpoint records the set of branches that hold a durable table-manifest base (`owned_table_count() > 0`) as a **new snapshot section kind** (proposed `SNAPSHOT_FLUSHED_BRANCHES_SECTION_KIND = 4`; payload `u32 count || 16-byte branch ids`). Section kinds are extensible: `validate_section_kind` rejects only 0 and recovery skips unrecognized kinds. No database-manifest version bump; one new golden vector.
- **Recovery:** Phase 1 (`lifecycle/recovery.rs`, seeded branch) and Phase 2 (`durable/bootstrap.rs::recover_per_branch_table_manifests`, non-seeded branches) drive orphan detection off the recorded set: a member whose table manifest is present combines as today; a member whose manifest is absent is an orphaned delta → discard its installed snapshot rows, recover its WAL-contiguous prefix, record `RecoveryFaultKind::MissingTableManifestBase` (DataLoss health); a non-member is a self-contained full snapshot → keep.
- **Lift:** remove `non_seeded_branch_has_durable_base` from `checkpoint_structural_deferral` and the stricter `non_seeded_branches_present` predicate from the close path; keep `any_branch_holds_unmaterialized_inherited_layers` (fresh-fork window, #2798). The guard regression `multi_branch_checkpoint_defers_so_lost_non_seeded_manifest_recovers_cleanly` flips to "checkpoint completes and recovery is clean per branch".
- **Dropped:** the multi-branch flush-watermark path (#3598's naive fix). Unsound to exclude `_system_`, pointless once the checkpoint runs, and would need the heavier database-manifest bump. #3598 is retitled to the close/multi-branch checkpoint fix.

### 3.3 Bounded checkpoint delta

`publish_checkpoint_rows` builds its sections (row delta, retained timeline, extras) and measures their total against the request's cap with the pure `checkpoint_delta_cap_decision(total_payload, cap) -> { Fits, MustFlushFirst }` — the same `>` rule the container encoder enforces, so exactly the cap still fits — **before** anything is published. `MustFlushFirst` returns a typed `LifecycleCheckpointStatus::DeferredDeltaExceedsCap` carrying the measured bytes; nothing is published, no id is consumed, no follow-up runs. It is deliberately **not** a `CheckpointStructuralDeferral` variant: that registry exists so every enqueue site can cheaply evaluate the same catalog-level predicate, and a size-based decision is only knowable after the sections are built. On the deferral the runtime chains a flush and a retried checkpoint with the same options, once per visible version, on all three checkpoint paths (sync runner, background publish step, explicit verb). **Until slice 12 the chained flush is scoped to the seeded branch:** flushing a non-seeded branch gives it a durable table base, which trips the orphaned-delta guard and would block every later checkpoint (for `_system_` that would be a regression on the common shape). Slice 12 lifts that guard and switches the chain to a global flush so a non-seeded branch's bloat drains too. The 64 MiB cap stays (DUR-017: bounded recovery decode).

### 3.4 Snapshot prune modes

`SnapshotPruneMode { Superseded, ReconcileToAttested }`. `Superseded` deletes `id < manifest_live_id` — never `id ≥ live`, so it is safe against an in-flight publish — and runs after every `Completed` checkpoint and at close. `ReconcileToAttested` deletes every `id != attested_id` and runs only in the open reclaim window, where no publish is in flight, reclaiming crash orphans. Both require the existing Complete retention proof (`build_retention_proof_from_facts`) and never delete the attested snapshot. The explicit newest-N verb stays for callers.

### 3.5 Observability (one canonical path)

The bytes the CLI prints, the SDK returns, the DST oracle asserts, the ratchet gates and the field check reports are the same facts from storage `diagnostics()`; `dbsize.py` becomes a cross-check only.

- **`ReclaimLedger`** (per runtime, `crates/storage/src/lifecycle/reclaim_ledger.rs`): last mark/sweep/purge/prune/truncation as `ReclaimEvent { outcome: ReclaimOutcome, reason: ReclaimDeferralReason, bytes_reclaimed, objects_affected, at_version }` (typed, never text), last-known orphan bytes with `as_of`, last quarantine bytes, pending reclaim tasks, last idle/open wake. Fed by a pure, truth-tabled `classify_reclaim(&MaintenanceSummary)` at each runner's completion site. Replaces the `perf-trace` statics as the product surface (rule 9).
- **`DiagnosticsDetail { Live, Audit }`** on `DiagnosticsRequest`; `DiagnosticsFootprintReport` (Live, zero I/O: live table bytes via a new `LifecycleDurableTableCatalog::total_object_bytes()`, WAL retained/active bytes + watermark, live snapshot id, ledger last-knowns; Audit, opt-in I/O: fresh orphan mark, per-snapshot bytes and superseded count, quarantine inventory, per-segment WAL reclaimable-vs-tail) and `DiagnosticsReclaimReport`; the never-filled `DiagnosticsQuarantineReport` gets populated; cache mode = unsupported.
- **Engine:** `PersistenceAdapter::storage_diagnostics` passthrough (Global scope covers both branches) → canonical `AdminService::storage_footprint(branch, FootprintDetail)` → `Database::storage_footprint`. D4 public types (`StorageFootprint`, `StorageFootprintOptions`, `StorageReclaimStatus`, `ReclaimEvent`, `ReclaimOutcome`, `ReclaimDeferralReason`, `FootprintDetail`; `#[non_exhaustive]`) with `stratadb` facade re-exports. Testkit seam `DurableLocalOpenOptions::with_maintenance_scheduling_policy_for_test` (named feature, mutation `exclude_re`).
- **Wire:** `admin.storage` (`strata . admin storage [--audit]`), `admin.metrics` as the template: `Command::Storage`, `Output::Storage(AdminStorage)` with fields `live_table_bytes, unreferenced_bytes, quarantined_bytes, superseded_snapshot_bytes, wal_reclaimable_bytes, wal_tail_bytes, total_bytes, reclaim_outcome, reclaim_deferral_reason, pending_reclaim_tasks, audit`; `admin.yaml` entry with `as: size` display; prose, example, fixtures, full IDL chain, `admin.txt` golden, Python SDK vendoring.

## 4. Slices: implementation and tests executed together

Every slice is one PR: its implementation and its tests land together, TDD (red first), with the invariant check and review before merge, ≤ 1,500 LOC. Storage-level tests open a **two-branch** runtime (an empty non-seeded root beside the seeded branch, mirroring `_system_`) under `DeterministicInline` with the manual clock; engine-level tests get the real topology for free. Tests assert typed outcomes and byte facts read from `diagnostics()`, never display text and never a directory walk. Every pure decision fn is truth-tabled and has a call-site test (mutation gate). Existing tests that pin the old contract are rewritten in the slice that changes the contract, never deleted. Fault-injection tests (`-p strata-storage --features fault-injection`) ride the slice they cover.

Landing order: 0 → 1 → 2 → {3, 4, 6, 11} in parallel worktrees → 5 → 7 (the user's 952 MB shape is fixed here) → 8 → 9 → 10 → 12 (island shape) → 13 → 14 → 15.

## 6. Risks and boundaries

- Slice 12 is durability-critical (per-branch discard must compose with shared-WAL replay); isolate it, DST + crash harness before merge, invariant check on ARCH-008, DUR-017, COW-001.
- Close latency: bounded by `reclaim_budget` (object drain, default 500 ms) plus the delta cap (checkpoint); a debt-free close costs one inventory listing and a small checkpoint. `ReclaimBudget::Disabled` exists for latency-critical callers.
- DUR-018 keeps its meaning: the open wake arms the worker; reclaim runs during the session; a clean-close checkpoint is operation-time work. The catalog text is amended to say so (slice 15).
- D4 public types need reviewer approval (rule 32) and facade parity.
- Out of scope: version pruning posture (#3502 stays opt-in), event record format (#3594/#3595, after slice 15), the database-manifest version bump (not needed), the multi-branch flush-watermark path (dropped by design).
